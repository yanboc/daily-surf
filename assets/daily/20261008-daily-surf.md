1. **[Stale, Misattributed, or Late: Where Personal Memory Fails Before Generation](https://arxiv.org/abs/2610.10265)**
   - 元信息：2026-10-07（abs：Submitted on 7 Oct 2026；cs.AI；UC Berkeley / Haas）；预印本；主题标签：Agent Memory / 生成前 prompt 级失效 / 键控 supersession·身份后验·弃答闸 / LoCoMo·LongMemEval；分级：S
   - 核心问题：个人记忆层通常只看终答是否正确，却掩盖生成前三类失败——记忆块里有过期值（stale）、同名他人的值（misattribution）、或超截止未送达（late）。终答分能否拆开「干净 prompt」与「当前值+过期值并存但碰巧答对」？键控 supersession 在键分配不完美时还买到什么？
   - 机制/设计：以 Personal Fact Memory（PFM）作参考层：事实带实体、参与者、可选槽键 \(\kappa\) 与活动区间 \([a_f,b_f)\)；同键新值原子 supersede 旧值，旧值留作历史（Proposition 1：每键至多一个 active）。服务侧指标：current-value recall、stale exposure、misattribution、clean retrieval（含不可答题的弃答）、截止前送达。身份用实体后验 \(\pi_t(e)\)（参与者 / 图关联 / 近因）；弃答分 slot gate（需槽清单）与 schema-free margin gate。对照：同库上 BM25/Dense/Hybrid ± validity ± 参与者字段；键分配测规则抽取、四类 LLM assigner、LongMemEval 开域 merge。
   - 证据：受控修订基准 5 种子×1,200 查询；键控库 stale=0（Wilson 上界 0.005）、clean 0.877 vs 无键 70.3% stale / clean 0.247。共享 active 库与参与者后，BM25+validity+\(P_t\) clean 0.873 相对 PFM 0.877，TOST 在预置 ±0.02 等价（\(p=0.038\)）。LLM 键分配键召回可 >0.98 但 clean 低于规则抽取（跨槽 false merge）；LongMemEval 32 道 verbatim 更新题上 merge recall ≤0.062，stale 仍 0.594–0.719。LoCoMo 同名说话人单库 wrong-person 暴露 0.543，参与者过滤降至 0.301。冻结 qwen2:7b / llama3.2:3b 会把 prompt 错误写进生成；预填延迟远大于检索（无记忆 TTFT 325 ms → 有块 1.22 s）。
   - 局限：正文 Limitations——受控基准模板族、全局唯一值 token、已知槽清单；LongMemEval 仅 2,587 轮 / 32 道 verbatim 更新题；LoCoMo 主要测出处暴露而非答召回；均非真实用户私库。Proposition 1 不保证语义正确；身份后验在同名归一化实体上失效；schema-free 弃答与槽闸不可互换。失败条件：只看终答 Acc；或假定「上了 supersession」即无 stale（开域键没合上时旧值仍 active）；或把排名规则当跨人访问控制。
   - 对办公 Agent 或 Agent 基础设施的意义：把「会议改点 / 同事同名 / 邮件续写」类记忆验收钉到**进入模型前的块是否干净、对谁、是否及时**。生产可对标：写路径键合并不达阈值则禁止宣称时效保证；同名实体要出处隔离而非只靠 BM25；不可答必须可测弃答；延迟 SLA 量预填而非检索 p50。

2. **[Know the Shape, Find the Fault: Topology-Conditioned Diagnosis of Multi-Agent LLM Failures](https://arxiv.org/abs/2610.10126)**
   - 元信息：2026-10-07（abs：Submitted on 7 Oct 2026；cs.MA / cs.AI；北航）；预印本；主题标签：Multi-Agent / 通信拓扑×失败模式 / TSE 拓扑恢复·TC-Judge 条件诊断 / MAST-14·MAScope-Bench；分级：S
   - 核心问题：多 Agent 协同失败时，轨迹上相似症状可能对应不同的信息传递、使用或校验问题。通信拓扑（Layered / Centralized / Decentralized / Shared Message Pool）能否作为结构线索区分失败模式？异构日志无显式拓扑标签时如何恢复，并用拓扑条件化低成本诊断？
   - 机制/设计：先在 MAST-clean 上检验拓扑–失败关联（\(\chi^2=409.9\), \(p=1.2\times10^{-70}\)），并归纳各拓扑特征失败锚（如 Layered 信息丢失、Centralized 校验漂移、SMP 语义漂移、Decentralized 角色僵持）。MAScope 两阶段：(1) **TSE**——压实/匿名化 → 抽取 ≤24 条 control/use/feedback/pool_read/independent 关系（须引用证据 span）→ 规则校验+有界修复 → 结构标签得 \(\hat\tau\)；适配 LangGraph/AutoGen/CrewAI/ChatDev/MetaGPT/Magentic/Simple Chain；(2) **TC-Judge**——用 \(\hat\tau\)、冻结的拓扑经验先验 \(\pi_{\hat\tau}\)（14 个 MAST 码发生率，探索集 400 条与评测集分离）与短失败签名，零样本一次 JSON 出 MAST-14 比特向量。固定编排下拓扑可跨执行复用。
   - 证据：MAScope-Bench 共 2,220 条（MAST-clean 851 / Inject-Mix 961 / LG-Ctrl 408）。TSE 在 MAST-clean 拓扑准确率 93.8%（798/851）；LG-Ctrl 控框架后 76.5%，SMP 最难 56.9%。零样本：真拓扑将 gpt-mini Macro-F1 从 0.173→0.350（+102%），gpt-5.4 0.372→0.399；预测拓扑端到端 0.346（相对 oracle −0.004）。监督基线 LOFO 大幅掉点（Flat-GBM 0.490→0.226）。固定编排下投影成本：含一次拓扑抽取后约相当于反复 gpt-5.4 诊断的 6%。
   - 局限：正文无独立 Limitations；从实验可知 MAST-clean 无 Decentralized、框架与拓扑常绑定，LOFO 同时转移二者；先验来自探索切片非在线自适应；诊断输出为 MAST 码向量而非根因定位/自动修复。失败条件：把「框架指纹可分」当拓扑可迁移（监督模型 LOFO 会塌）；或动态改拓扑却仍复用旧 \(\hat\tau\)；或 SMP 恢复不准时仍盲信签名。
   - 对办公 Agent 或 Agent 基础设施的意义：给「调研→撰稿→审阅」类办公多 Agent 一条可运维诊断合同——**先恢复/声明通信拓扑，再按拓扑先验读轨迹**。生产可把 Layered 交接丢需求、Centralized 枢纽验收漂移、消息池意图漂移写成值班手册；拓扑稳定时摊销一次提取、用小模型做边际诊断。

3. **[ReFold: Training-Free Reversible Inter-Turn Context Folding for Long-Horizon Agents](https://arxiv.org/abs/2610.07863)**
   - 元信息：2026-10-06（abs：Submitted on 6 Oct 2026；cs.CL / cs.AI / cs.LG；UCSB + Intel）；预印本；主题标签：Context Engineering / 可逆回合折叠·跨回合去重 / chunked 渲染保前缀缓存 / 长程 Agent 服务成本；分级：S
   - 核心问题：长程 Agent 每步重发整段 append-only 历史，上下文与 KV 二次增长；既有「预测式」裁剪常引入额外模型调用、打废前缀缓存、或永久丢内容。能否在不改工具/环境的前提下，只压缩**渲染给模型的上下文**，且误删可从历史一键恢复？
   - 机制/设计：训练无关渲染层 \(c_t=R(h_t)\)，历史 \(h_t\) 不变。两算子：(1) **Deduplication**——跨回合相同观测 span 留首次、后续换 stub（含路径/步号与 `restore` 提示）；(2) **Folding**——在常规回复中要求 `PROGRESS` + `⟨STALE⟩`（仅接受近 \(k\) 步内索引），把声明完成的整回合压成一行 note。**Chunked rendering**：边界 \(b_t\) 每 \(k=3\) 步推进一次，边界内严格 append-only 以保前缀缓存；误折叠靠 harness 拦截 `restore <step>` 从历史追加原文，或重跑命令且新观测豁免再压缩。接入仅需渲染钩与提示词信号。
   - 证据：统一 mini-swe-agent + vLLM 前缀缓存；五基准×50 题×两骨干（Qwen3.6-27B / 35B-A3B）。全窗 \(w=8\)：resolve 差 −1～+3/50（在运行变异内）；token −18%～−60%，峰 KV −30%～−58%，估费最高约 −45%（如 Verified 27B：965→505k token，1.71→0.83 GiB）。受限：32k 预算 compaction −92%；\(w=48\) 排队 8.96→0.02 s、resolve 7→32/50。消融：渲染开销 0.4 ms/步 vs compact 3.3 s；关 chunking 前缀命中 87%→51%；关可逆则约 1/3 观测 token 不可恢复。动机研究：仅剪工具输出无法钉住预算（agent 自身推理亦累积）。
   - 局限：正文无独立 Limitations 节；评测主战场为仓库/终端编码 harness，非邮件日历；折叠依赖模型自觉标 `STALE`；去重偏精确匹配。失败条件：无 restore 通道却激进折叠；或每步重渲染打废前缀缓存；或把 ReFold 当跨会话长期记忆（它管单会话渲染，与检索记忆互补）。
   - 对办公 Agent 或 Agent 基础设施的意义：把「多附件阅读 / 反复打开同一文档 / 长工单」的上下文合同从「预测删什么」推进到**渲染压缩 + 历史可逆 + 分块保缓存**。生产可把 stub/fold + `restore`、chunk 边界、compaction 次数与并发排队延迟列入 harness 回归，再叠加办公写闸。

   - 证据：[Release dotnet-1.24.0](https://github.com/microsoft/agent-framework/releases/tag/dotnet-1.24.0)；[README](https://github.com/microsoft/agent-framework/blob/245d428/README.md)（HITL / checkpoint / governance）；PR [#8834](https://github.com/microsoft/agent-framework/pull/8834)/[#8873](https://github.com/microsoft/agent-framework/pull/8873)/[#8832](https://github.com/microsoft/agent-framework/pull/8832)；实现 [`InvokeMcpToolExecutor.cs`](https://github.com/microsoft/agent-framework/blob/e626cef/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/ObjectModel/InvokeMcpToolExecutor.cs)（`HeaderSnapshot` / restore 再审批）、[`InputConverter.cs`](https://github.com/microsoft/agent-framework/blob/7634356/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/InputConverter.cs)（`ConvertMcpApprovalRequest` / `ToolApprovalIdMap.ResolveEntry`）；官方文档 [learn.microsoft.com/agent-framework](https://learn.microsoft.com/en-us/agent-framework/)。
   - 局限：头绑定依赖进程内快照，长休眠 restore 必须再审；#8873 审稿曾指出映射键若仅派生自非唯一 provider call id，碰撞仍可能污染历史（需运维侧保证唯一性）。失败条件：把「用户点了批准」当成可改参/改头后仍有效；或在无 `ToolApprovalIdMap` 的会话上假设 Foundry 回放能对齐审批。
   - 对办公 Agent 或 Agent 基础设施的意义：给「发信 / 改表 / 调工单 MCP」一条可测合同——**批准绑定调用快照，传输凭据不进审批文案与检查点，回放按映射还原请求 id**。生产可与 propose/execute 分工具并列验收：改头→必须再审；缺映射→fail-closed；双点批准→单次消费快照。
