1. **[Not All Memories Are Equal: Hierarchical Collaborative Memory for Validity-Aware Retrieval in LLM Agents](https://arxiv.org/abs/2609.30289)**
   - 元信息：2026-09-28（arxiv cs.CL new listings；v1 submitted 2026-09-09）；预印本；主题标签：Agent Memory / 团队·个体分层冲突 / 有效性感知检索 / HiCoMER / ORR·CRR；分级：S
   - 核心问题：协作场景里记忆是异质且演化的——团队记忆记决议/协议/当前共识，个体记忆记观测/执行痕迹/中间进度；扁平语义检索常捞到「相关但已过时或与团队共识冲突」的个体记录，导致下游 QA 偏离现行有效状态。
   - 机制/设计：HiCoMER 三模块。(1) **Hierarchical Memory Conflict Updater**：按时间对齐组 \(G_t=M_t^{\mathrm{Team}}\cup M_t^{\mathrm{Individual}}\)，先用稠密检索取历史 Top-\(K\)；组内以 Team 为权威修订 Individual，再以维护后的当前组修订历史候选；对每条记忆预测 relation∈{compatible,neutral,contradiction} 与 action∈{keep,revise}，SFT 后再用 GRPO（一致性/最小修订/格式奖励）。(2) **Validity-Aware Memory Retriever**：Top-\(N\) 语义召回后，用交叉编码器 \(S_{\mathrm{sem}}\) + 含维护内容、Team/Individual 类型嵌入与维护时间戳的 MLP \(S_{\mathrm{val}}\)，\(S_{\mathrm{final}}=S_{\mathrm{sem}}+\lambda\log\sigma(S_{\mathrm{val}})\)，pairwise 排序压过时/冲突负例。(3) **Memory-Grounded Answer Generator**：对检索结果按 Team>Valid>近维护时间做矛盾消解后再生成。评测自建 ALI / PROTAC 生物医学协作流（PubMed 反模拟 12 周生命周期，共 1,781 组 / 17,718 文档 / 621 注入冲突）。
   - 证据：ALI + Llama-3.1-8B：ORR@5 14.18（Mem0 28.63、G-Memory 29.74、Flat RAG 45.83），CRR@5 84.87，Decision F1 64.61，ROUGE-L 52.93，NDCG@10 68.74。Qwen2.5-3B 仍 ORR@5 16.07 / CRR@5 82.34。PROTAC 同骨干 ORR@5 15.37 / CRR@5 82.74。消融去掉 Updater 或 Validity Retriever 使 ORR@5 回升至约 29–30、Decision F1 掉约 9pp。Updater 组件：Llama SFT+GRPO Conflict F1 87.88、Maintenance Acc 91.17。人评 17 人×10 任务：Memory Precision 4.11 vs Mem0 3.73，Intervention Usefulness 4.04 vs 3.68。
   - 局限：Limitations——噪声/错位的 Team·Individual 记录会伤维护与答题；评测主域为生物医学协作反模拟，非真实企业日志。失败条件：把扁平语义/近因检索当「现行 SOP」；或写闸不区分团队决议与个人实验笔记，使已废止协议仍被召回执行。
   - 对办公 Agent 或 Agent 基础设施的意义：直接映射「制度/会议决议 vs 个人工单笔记」——共享记忆写入与检索必须先做分层有效性维护，再按 Team 权威+有效性重排。生产可把 ORR/CRR 类指标挂进记忆回归，并在答客户/改流程前禁止未维护的个体旧日志压过团队共识。

2. **[Probing Stability–Plasticity Tradeoffs in Agent Memory through Cognitive Experimental Paradigms](https://arxiv.org/abs/2609.30558)**
   - 元信息：2026-09-28（arxiv new listings / cs.CL→cs.AI cross-list；v1 submitted 2026-09-24；标为 EMNLP 2026 Main）；预印本；主题标签：Agent Memory / 稳定–可塑性诊断 / MemProbe / 溯源与时序保真 / 分裂扰动；分级：S
   - 核心问题：两套记忆系统可有相同终答准确率，却一个过塑（弱证据就覆盖）、一个过稳（合法更新进不去）；现有榜多报 Acc/F1/任务成功率，无法拆出更新、保全、归因与时间组织行为。
   - 机制/设计：MemProbe 把认知范式写成可复用试验规格——**Interference / Misinformation / Consolidation Strength / Reconsolidation Window**，每 trial 固定编码→扰动→探针，并定义应更新 vs 应保全条件。指标：Plasticity / Stability / SP-Balance，以及历史/来源/时序保真；失败归入 provenance loss、historical overwrite、under/over-update、split-evidence miss 等。示范套件 56 episode / 1,246 session / 224 probe（含个人·工作·Agent/工具态事实与 12 个分裂扰动）；增量协议为 Reset→逐 session Ingest→仅用维护后记忆作答。评测 Mem0、Graphiti/Zep、LangMem、Cognee、A-MEM、MemoryOS，统一 Gemini-3-Flash reader。
   - 证据：Overall：A-MEM 88.4%≈Full-context 88.8%，Cognee 81.7%，Mem0 41.5%。SP：A-MEM Plast./Stab. 91.1/85.7（SP-Bal 88.3），Cognee 75.0/88.4（稳偏），Mem0 28.6/54.5。Graphiti vs LangMem 总精度无显著差（\(p>0.37\)），但 previous-value 96.4 vs 67.9（Bonferroni 后仍显著）——同 Acc、反维护策略。来源保真普遍弱于现值（Mem0 source 17.7%、Graphiti 41.9%；Full-context 同 reader 仍仅 66.1%）；人工分源错误为 storage-side vs read-out，跨系统差主要在存储侧丢失。分裂扰动：Naive/Time-aware RAG Split CV 均 8.3%，Oracle RAG 91.7%，瓶颈在检索两侧证据。换 Qwen3-32B reader 排序 Spearman \(\rho=0.94\)。第二套独立 40 episode 复现 A-MEM 顶 / Mem0 底与源保真短板。
   - 局限：Limitations——示范套件域/语种/部署面有限；统一 reader+结构化打分非各系统原生端到端；对话表层有 LLM 生成偏见。失败条件：只用总 Acc 选型（会把过塑/过稳抹平）；或把「能答对现值」当成已保留来源与更新序列。
   - 对办公 Agent 或 Agent 基础设施的意义：给 CRM 偏好、项目负责人、工具配置等「会改也会被谣言污染」的办公记忆一条验收合同——上线前用干扰/误导/巩固/再巩固探针出 SP 画像，并把源与时序保真、分裂证据召回列入门禁，而不是只盯 LoCoMo 式回忆分。

3. **[Learning What to Skip: Counterfactual Credit Assignment for Efficient Multi-Agent LLM Workflows](https://arxiv.org/abs/2609.30734)**
   - 元信息：2026-09-28（arxiv new listings；v1 submitted 2026-09-25）；预印本；主题标签：Multi-Agent / 工作流组件跳过 / 反事实信用分配 / 校准·域原生护栏 / 顺序 fall-through；分级：A
   - 核心问题：多 Agent 工作流固定跑完 planner/executors/verifier/summarizer 既费 token，也可能用错误中间态覆盖正确结果；路由只决定「造什么图」，回答不了「前缀已给定后，哪个未来组件还值得跑」。全轨迹日志无法识别跳过某组件后的回报（Proposition 1）。
   - 机制/设计：LW2S。(1) 对每任务收集全工作流 + 单组件跳过干预，得 \((x,h_s,a,Z_a,\ldots)\)，\(Z_a=\mathbb{I}[R^a\geq R^{\mathrm{full}}]\)。(2) 按决策阶段/动作训 TF–IDF+结构化特征的 logistic 安全模型。(3) 持出校准：阈值须满足退化计数/Wilson UCB/不低于全工作流回报，多源取交集。(4) 域原生护栏 \(G_a\)（数学数值一致、MMLU 选项一致作压力、MBPP 可见单测双过）；失败则拒跳。(5) 安全集内选最大节约；MBPP 两阶段：先尝试 skip verifier，被拦则跑 verifier 再考虑 skip summarizer（fall-through，不合成未观测联合干预）。主模板五角色；另测 debate-refine 拓扑。
   - 证据：同协议对照 RouteLLM / GraphPlanner / AutoMix / Prompt-LLM。Qwen2.5-7B：MATH verifier Acc 66.4（Full 65.2）Save 25.1% 且 0 退化；GSM8K Save 20.6% 保 88.5%；MMLU Save 8.6% 保 73.0%（1 任务退化）；MBPP slice0 Acc 70.0/Save 28.5%，slice1 保 63.0%/Save 31.2%（固定 skip verifier 会掉到 61.0%）。Mistral-7B 六设置 0 观测退化。slice1 组件账：LW2S 选 57 verifier + 43 summarizer skip。护栏消融：AST 相等在 slice1 选 94 任务却 2 退化；双执行器测过可拦失败。辩论拓扑：LW2S 68.0% vs Full 67.0%，Save 16.65%。边界：MMLU 执行器共识 A/A、verifier 改到金答案 C——共识≠正确。
   - 局限：正文无独立 Limitations；校准为经验证书、非分布漂移保证；主评数学/QA/代码而非办公工具链；单测护栏判别力受套件大小限制。失败条件：把执行器一致/AST 相似当跳过证书；或无 fall-through 时在早期拒跳后不再回收后期 summarizer 冗余。
   - 对办公 Agent 或 Agent 基础设施的意义：把「多角色审批/复核/汇总」从固定流水线改成**带反事实标签的条件跳过**——生产应为写闸前的 verifier、纪要 summarizer 等贵组件采 skip 干预日志，用可审计护栏（工单状态、单测、人审信号）替代口头共识，并允许前闸拒绝后后闸再省。
