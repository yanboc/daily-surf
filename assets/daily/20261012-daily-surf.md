1. **[Forgetting is Not Always Bad: A Neuro-Inspired Memory Repair Mechanism for Poisoned LLM Agents](https://arxiv.org/abs/2610.13267)**
   - 元信息：2026-10-09（abs：Submitted on 9 Oct 2026；Mon 12 Oct 2026 列表公告；cs.AI；西北工业大学 / 新加坡国立大学）；预印本；主题标签：Agent Memory / 记忆投毒修复·功能遗忘 / 扰动探针·多维激活诊断 / EHRAgent·ReAct·MAS；分级：S
   - 核心问题：记忆增强 Agent 一旦写入投毒条目，常被 top-K 检索并劫持推理与工具调用，还会形成伪正向强化环。现有防御多靠外挂静态隔离或持续在线审计，内存效率低、算力开销大。能否在**不改模型权重、不硬删**的前提下，让 Agent 内生地选择性「功能遗忘」恶意记忆？
   - 机制/设计：**DREAM**（Dynamic Reactivation for Engram Attenuation in Memory）三阶段、训练无关。(1) **隐式再激活**：对库中每条记忆 embedding 加各向同性弱高斯噪声 \(\tilde{v}_i=v_i+\epsilon\)，零知识压力测试；(2) **自适应异常诊断**：多维激活强度 \(R_i=\mathrm{sim}(\tilde{v}_i,v_i)+p_{\mathrm{ret}}(\tilde{v}_i)+E_{\mathrm{coh}}(\tilde{v}_i)\)（几何稳定 / 相对检索竞争力 / 语义相干能量），阈值 \(R_{\mathrm{th}}=\mu_R-\eta\sigma_R\)，可疑则抬升嫌疑分 \(s_i\)、否则衰减；(3) **突触式权重演化**：衰减率 \(\lambda_i=\lambda_0(1+k s_i)(1-c_i)\) 耦合在线巩固信号 \(c_i\)；良性且高效用走再巩固 \(w\leftarrow w+\alpha_{\mathrm{rec}}(1-w)\)，否则指数衰减 \(w\leftarrow w\exp(-\lambda_i)\)，权重进加权检索。离线探针 + 在线任务效用反馈。
   - 证据：AgentPoison（DPR）——GPT-5.4-mini 上 EHRAgent/eICU ASR-r/a/t 自 100/100/100 降至 **2.14/2.14/2.14**，ACC 70.83→**85.03**；MIMIC-III 与 StrategyQA 上 ASR 近零，ACC 54.55→62.34、26.20→61.20。Claude-Haiku-4.5 同向。MINJA：eICU ASR 90.71→**1.60**（ACC 69.52→77.01）。MAS（MISINFOTASK）：FS **6.038** / TSR **92.96%**（A-MemGuard 6.233 / 89.90）。效率：10 查询批 178.42s / 46,484 tokens，相对 A-MemGuard 约 **2.13×** 更快、token −**37.7%**。消融：去 \(E_{\mathrm{coh}}\) 使 eICU ASR-r 升至 81.82；投毒 4→64 条仍压住 ASR。
   - 局限：附录 A——若攻击者掌握内部探针机制，可优化投毒记忆使其在扰动下仍稳定，削弱异常信号；作者称现有威胁模型多为 query-only / 间接注入 / 黑盒，实现探针感知攻击需更强能力。正文无独立 Limitations。失败条件：只用困惑度/单维一致性过滤却宣称已修记忆投毒；或硬删条目而不保留可审计的权重衰减轨迹；或只报 ASR 不报良性 ACC。
   - 对办公 Agent 或 Agent 基础设施的意义：给「共享会议纪要 / 工单经验库」一条**写后修复合同**——强制投毒与语义伪装注入都要验收 ASR×ACC 双表，并用权重衰减而非不可逆删除。生产可对标：检索分必须乘记忆权重；巩固信号不得把未惩罚的恶意动作当成功经验；多 Agent 共享库上的投毒不得只靠外挂审计。

2. **[LongHarness: Advancing Agentic Reasoning over 100M-Token Corpora via Stateful Evidence Management](https://arxiv.org/abs/2610.13075)**
   - 元信息：2026-10-09（abs：Submitted on 9 Oct 2026；Mon 12 Oct 2026 列表公告；cs.AI；复旦 / 上海 AI Lab 等；联系 huangsongtao@pjlab.org.cn）；预印本；主题标签：Context Engineering / 证据–结论共演化·EvidenceBank 生命周期 / OfficeQA Pro·AA-LCR·LongBench v2；分级：S
   - 核心问题：语料级长上下文推理要在远超窗口的文档集上取证整合；现有 harness 把证据与演进结论缠进不断变长的交互史，易导致**无界探索**（检索膨胀却不闭合决策缺口）与**证据态漂移**（已得证据或更正未进入当前结论）。能否把证据与结论做成可演化的显式状态？
   - 机制/设计：**LongHarness**，模型无关。(1) 状态 \(S_t=(E_t,C_t,H_t)\)：源链接证据、证据链接结论与未决缺口、交互史；(2) **Evidence–Conclusion Coevolution**——结论缺口引导 search/read，新证据再经 \(R_\theta\) 修订 Conclusion State（claims / hypotheses / gaps），声明与推断分治；(3) **Evidence Lifecycle Management**——候选须引用已注册源 span，准入后跨轮持久；更正=新 active + 旧 superseded，撤回=retracted；计算与 final 由控制器校验证据引用；(4) 动作空间：search / read / upsert / revise / compute / final，预算与协议硬约束。
   - 证据：OfficeQA Pro V1≈100M token（697 文档）、V2=1,435 文档+跨源统计题；对比 Codex / Claude Code / RLM，每设置单次 run（附录 D 有三跑方差）。GLM-5.3-Flash：V1 Ex. **60.2%**（直连 15.8；Claude Code 48.1，+12.0 pp）、V2 **61.1%**（Codex 42.2，+18.9 pp）；Qwen3.8-Flash V1 **61.7%**。四基准 Avg Exact：GLM **70.3%** / Qwen **69.2%**。消融（GLM）：去持久态 V1/V2 −4.5/−7.8；去共演化 −5.3/−9.4；仅追加证据 −3.8/−10.0；去结论引导探索 −4.5/−7.8；改自由笔记 −6.8/−7.8。证据级：V2 上检索/编辑/变换条件成功率 87.8 / 87.3 / 79.7；V2 中位轮次仅 22→30（Claude Code 21→116）。
   - 局限：正文无独立 Limitations；主表 harness 为每设置单跑；缺答与运行失败计错；OfficeQA 为财政文档语料，非邮件/日历写副作用。失败条件：把交互史当已管理的证据态；或 append-only 堆积却不 supersede/retract；或 final 不校验 active 源引用；或只报检索覆盖率掩盖编辑/变换掉点。
   - 对办公 Agent 或 Agent 基础设施的意义：直接对标「百兆 token 制度/财报/制度库问答」——验收钉到 **EvidenceBank × Conclusion State × 源引用闸**。生产可对标：缺口驱动下一跳检索；冲突数值必须生命周期修订后再进计算；跨源复合题上轮次膨胀不得高于竞争 harness。

3. **[Temporal Evidence Forests for Long-Horizon Multi-Party Conversational Memory](https://arxiv.org/abs/2610.12874)**
   - 元信息：2026-10-09（abs：Submitted on 9 Oct 2026；Mon 12 Oct 2026 列表公告；cs.CL；北航 / 阿里巴巴）；预印本；主题标签：Agent Memory / 多方对话·时序证据林 / 局部密集聚类·UPDATE/EXPAND 结构化 / GroupMemBench·EverMemBench；分级：S
   - 核心问题：多方长对话里决策反复更新、状态随参与者与阶段演进；相关信息常在短时段内密集出现，状态转移又严格有序。现有时序记忆多把时间当元数据或检索线索，**不能**同时用时序结构恢复局部密集证据并重建完整事件进展。
   - 机制/设计：**T-MEM**，查询时构图、原对话不变。(1) **Temporal Evidence Discovery**：元数据扩展种子检索（BM25，k=36）→ 按 topic 对锚点时间戳 DBSCAN（ε=12h）→ 密度 \(\rho=|C|/\max(\Delta t,\delta)>\mu\) 的区间双侧 pad 12h → embedding Top-100 + LLM 标 KEY/SUPPORT/IRRELEVANT；(2) **Temporal Memory Structuring**：同 topic、时间与 stage 序约束下标 UPDATE（状态推进/替换）或 EXPAND（解释/支撑），否则 ROOT；超预算时按查询相关且父节点未覆盖的信息增益压缩非保护 span；(3) **Evidence Forest Linearization**：树按根时间、树内前序，序列化 \((i,\pi_i,r_i,d_i,t_i,a_i,x_i)\) 供答题模型，不泄露参考答案。
   - 证据：GroupMemBench / EverMemBench。Overall——GPT-5.5：**63.09% / 79.46%**（最强基线 HippoRAG2 54.50 / 71.04，+8.59 / +8.42 pp）；Deepseek-V4-Flash：**62.68% / 77.63%**（+8.05 / 相对 StructMem +6.50）。多跳/知识更新/时序分项领先。Exp-2：Top-36 key-evidence recall **72.8%**（BM25 Expand 56.6、HippoRAG2 61.5）。消融与附录显示时序发现与结构化均贡献；类别上不处处第一（如 abstention/term ambiguity 偶被 MemGAS/StructMem 超过）。
   - 局限：附录 H——(1) 时序扩展依赖粗锚点覆盖，k 过小则聚不起可靠 episode；(2) UPDATE/EXPAND 两关系会混澄清/质疑/辩护等细话语功能；(3) 基准元数据与交互比真实群聊更干净。分析侧：证据召回标注难穷尽合法替代链；LLM 答题+裁判有随机噪声。失败条件：只给消息打时间戳做排序检索却宣称已建事件进展；或全局 top-k 加大预算代替局部时序再开窗；或把林压缩删到丢 UPDATE 状态变更。
   - 对办公 Agent 或 Agent 基础设施的意义：给「多人群/频道里改期、改需求、改口径」类记忆一条**先按时段找回再按 UPDATE 链呈现**的合同。生产可对标：答题上下文须暴露 ROOT/UPDATE/EXPAND；知识更新与时序题分表；压缩不得吃掉带数值/时间戳的状态边。

3. **[Human-in-the-Loop Design for AI Agents](https://veduis.com/blog/human-in-the-loop-agent-design/)**
   - 元信息：2026-10-10（Veduis 工程博文；Curtis Harrison；约 12 分钟读；含退款邮件 Agent 路由伪代码与 8 点上线清单）；已发布；主题标签：办公 Agent 人机审批 / 邮件·退款外写 / 风险分层路由·评审队列 UX / 审计抽样防橡皮图章；分级：A
   - 核心问题：接入支持收件箱的退款 Agent 连续三周「看起来正常」，却在续费窗口外两天的同情叙事上自行判「符合政策」并外发 $1,140——无人看到邮件直至客户道谢。全自动在判断边上会安静放大错误；如何把人放在正确闸点，且评审队列真的被读而不是四秒一键？
   - 机制/设计：五类 Oversight 模式并用，而非处处人工。(1) **Approval Gate**：不可逆动作（外发邮件、退款、删记录）做到「工作做完停在临界点」，人 15 秒批后果；(2) **Confidence Routing**：金额×政策匹配×结构化置信度分档——例 <$50 高置信自动、<$500 入队、>$500/边缘案升级，阈值由业务定而非模型；(3) **Review Queue UX**：先写明文拟议动作，再给三条决策事实，Approve/Reject/一键改，按相似案批处理；(4) **Escalation Timeout**：默认 4 工作小时升经理队列、24 小时再升 owner；涉钱默认 stay blocked，禁止超时默批；(5) **Audit Trail** 记录提案、所见数据、模型/提示版本、审批人与时间，并支撑每周 2–5% 自动批 + 人工批冷抽样，同时盯 Agent drift 与 reviewer drift（中位审阅时长掉到读不完决策的阈值即告警）。退款邮件流水线：Intake→Draft（不发）→Score→Route→Act+log。
   - 证据：客户案例——约 900 张退款单/月，闸后约省 55 员工时/月、评审负担约 6–8 小时；day-31 医院叙事案现因严格政策匹配失败而升级给人。文内给出 `route(draft)` 伪代码与五模式对照表（审阅耗时与缺闸失败模式）。对照 EU AI Act Art.14 / NIST AI RMF 对人监督的监管压力。
   - 局限：数字来自作者交付经验与示意阈值，非公开复现实验；置信度依赖模型自报结构化分，未给校准曲线；未接具体邮件/支付厂商 API。失败条件：把「人人批」当默认导致疲劳橡皮图章；或涉钱超时 default-approve；或只有审批日志却无抽样与审阅时长监控。
   - 对办公 Agent 或 Agent 基础设施的意义：把邮件/表单/退款类外写的人审从「有个确认按钮」推进到**风险分层 + 可读队列 + 超时 fail-closed + 审计驱动抽样**。可与同窗 BSWEN 的「审批=持久记录、外写幂等」叠用：Veduis 管人看什么、何时看；BSWEN 管代码是否真拦、是否只生效一次。生产可对标：不可逆默认草稿；自动批必抽样；评审中位时长作健康指标。
