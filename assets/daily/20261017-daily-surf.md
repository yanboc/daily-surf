1. **[MemComposer: Learning to Assemble Memories for LLM Agents via Reinforcement Learning](https://arxiv.org/abs/2610.21091)**
   - 元信息：2026-10-15（abs：Submitted on 15 Oct 2026；cs.AI / cs.CL；UIUC / Amazon；30 pages, 8 figures, 14 tables）；预印本；主题标签：Agent Memory / 记忆组装·可变 k 与序 / ExPO·GRPO / τ²-bench retail·airline·telecom；分级：S
   - 核心问题：Agent 记忆库检索后，语义相似≠下游有用——选几条、按何序塞进上下文会改变成败，且最优 \(k\) 因域而异。现有方法多对单条记忆打分再取固定 top-\(k\)。能否把**组装后的记忆上下文**当作决策单元，用完整多轮任务成败来学「选哪些 / 选多少 / 如何排序」？
   - 机制/设计：**MemComposer** 在固定相似检索 top-\(n\)（主设 10）候选上，由 composer \(\pi_\theta\) 采样有序子集 \(S\)（\(0\le k\le n\)）。记忆库：冻结 executor 自 rollout \(N\) 条轨迹 + 事后 review，经一致性校验后固化 \(m=(\tau,r,v)\)。**ExPO**（GRPO）：每 query 采 \(G\) 组组装；每组用冻结 executor 跑 \(J\) 次，任务奖励为经验成功率，再减长度惩罚与格式惩罚；组内相对优势、不按组标准差归一化；全同任务结果的组丢弃（DAPO 式）；无 KL、不更新 executor/检索器/记忆库。主评 \(\tau^{2}\)-bench 三域，用户模拟器统一 GLM-4.7；每任务 4 trial，报 pass¹ / pass⁴。
   - 证据：Table 1——Qwen3-4B 宏均 pass¹ **50.8** / pass⁴ **32.5**（最强基线 Memento 45.0 / 26.7）；Ministral-3-8B pass¹ **63.5** / pass⁴ **40.0**（最强基线 MemRL 58.9 / 38.3）；12 个域级对比中 10 个最优或并列。相对最强基线记忆 token：全域均少 **16.9%**（4B）与 **4.9%**（8B）；retail 上分别少 26.9% / 35.2%。同集合重排：composer 序相对相似/反相似/长短序平均抬 pass¹ **+6.1**（Table 2）。训练后更敢选低相似位、成功轨迹占比 45.5%→35.6%（失败记忆亦可教操作）。零售训好的 composer 零样本迁到 airline/telecom 接近域内训；跨 executor、跨更强模型记忆库仍受益（Figure 6）。
   - 局限：正文 Limitations——仅 4B/8B executor，未刻画 frontier 是否仍需独立 composer；序只靠序列级奖励隐含学，\(G{=}8\) 相对阶乘子集空间，无全排列 oracle；只评轨迹+review 的过程记忆，未覆盖语义事实库或用户 episodic。失败条件：只按相似 top-\(k\) 却宣称已做记忆组装；或只优化单条效用却不测序与可变 \(k\)；或单次 rollout 当确定性奖励仍宣称已控 agent 随机性。
   - 对办公 Agent 或 Agent 基础设施的意义：客服/工单类办公流程可把「规程记忆怎么塞进上下文」验收钉到 **组装策略可学、token 与 pass¹/pass⁴ 同表、冻结工具 Agent**。生产可对标：可变 \(k\) 与序是否相对固定 top-\(k\) 有净增益；跨域/跨骨干迁移是否免再训；禁止只报检索召回。

2. **[MemScope: Evolving Agent Memory Architectures through Localized Code Repair](https://arxiv.org/abs/2610.21170)**
   - 元信息：2026-10-15（abs：Submitted on 15 Oct 2026；cs.AI；中科院计算所 / 国科大 / 美团；Miao Su 等）；预印本；主题标签：Agent Memory / 记忆架构就地修补·Patch Agent / 轨迹+内存态定位 / GAIA·xBench·ALFWorld；分级：S
   - 核心问题：自演化常改记忆**内容**或用分数/摘要驱动**整段重写**记忆架构代码——粗反馈无法区分「没写入 / 检索滤掉 / 早退未注入 / 已给对指导仍做错」，导致改错靶、大范围重写。能否用细粒度执行证据做**局部、就地**的 provider 代码修复？
   - 机制/设计：**MemScope** 把记忆 skill 拆成 SKILL.md + 可执行 provider（`memory_retrieval` / `memory_storage`）与独立 runtime bank（Agent Skills 形）。Executor 分段跑任务；段准确率低于历史最优超 \(\delta{=}0.05\) 且失败≥1 则触发 **Patch Agent**：只读工具查 raw trace、memory store（stats/list/read/query 含选择决策）、provider 代码与 Patch History；提出精确 old→new 替换，校验语法/类身份/方法名（后段加 import 与孤立检索），保留 bank；证据不足可 `no_patch`。主演化自 DynamicCheatsheet；Skill Bank 初含 MemEvolve 的 12 个人工 skill；Executor 为 Flash-Searcher（GAIA/xBench）或文本动作环（ALFWorld）。
   - 证据：DeepSeek V3.2 上 MemScope+Flash-Searcher：GAIA val pass@1 **83.64%**、xBench **78%**（MemEvolve+ 为 67.88% / 70%）。配对空库起步的 xBench 70 题：演进 vs 原版 DynamicCheatsheet——DeepSeek **55/70 vs 49/70**、Kimi **53/70 vs 50/70**；保留原成功约 96%/92%，恢复失败多于回归。ALFWorld valid_unseen 同采集序列：**71.64%**（48/67）vs 原版 50.75%、ALMA 67.16%。消融（Table 5）：Trace+Memory **86.67%** vs Trace-only 70.00% / Summary-only 63.33%；14 次归档过渡中位代码变更比 **4.4%**、中位改 1 个函数。案例：summary 只加泛化校验文案，trace 定位并删掉 `MemoryStatus.IN` 早退；另有已给对指导却失败时主动 `no_patch`。
   - 局限：无独立 Limitations 节；主线自 DynamicCheatsheet 出发，演化窗约 30 开发任务；GAIA/xBench 以 GPT-4o-mini 判分；Figure 3 对比中代码与记忆态同时变，非纯代码消融。失败条件：只用分数/摘要驱动整库重写却宣称已定位失败；或改检索阈值却不查「指导已注入仍失败」；或把大段生成新 provider 当局部修补。
   - 对办公 Agent 或 Agent 基础设施的意义：把「记忆 skill / 连接器规程代码」的在线演进验收钉到 **轨迹+银行+代码三联诊 + 变更面可计量 + 可拒绝修补**。生产可对标：补丁中位 diff；相对 summary-only 的诊断准度；不可用「整文件重生」冒充局部修复。

3. **[TEM: Temporal State Tracking Memory for Large Language Model Agents](https://arxiv.org/abs/2610.21900)**
   - 元信息：2026-10-15（abs：Submitted on 15 Oct 2026；cs.CL；浙江万里学院；Pengfeng Song / Yunkai Zhuang / Liye Shi；16 pages, 5 figures, 8 tables）；预印本；主题标签：Agent Memory / 事实版本组·historical 标签 / 源序证据 / 状态更新·LoCoMo hybrid；分级：A
   - 核心问题：跨会话状态（住址、雇主、偏好）会多次更新，旧值对「过去怎样」仍有用；仅保留最新、或堆原始会话却不标版本，都会让生成器把旧值当当前或混淆关系。如何在**不训练骨干**下把版本状态显式送进答题证据？
   - 机制/设计：**TEM** 按 (subject, relation) 建版本组，追加新 session 事实（冻结模型抽取 + 格式/一致性校验），用完整组上最大 source index 判定 historical；检索按相关性加权（residence/employer 1.0 … likes 0.6）最多 15 条，**不因年龄惩罚**，再按源序排列并对被取代版本贴 `[historical]`。事件摘要与原对话轮作补充；**TEM-Status** 评状态更新，**TEM-Hybrid-State** 在固定证据预算下混用。对照：Overwrite / Unmarked（同内容同源序无标签）/ session-aware RAG / full context。
   - 证据：60 人设 × 600 session → 420 题。四骨干（Llama-3.1-8B / Qwen3.5-4B·9B / gpt-oss-20b）整体 key-entity hit **75.71–97.62%**；相对 Unmarked 仅加标签抬 **+17.14～55.95** pp（事实与源序固定）。历史住址子集：Overwrite 0–8.33%、Unmarked 41.67–81.67%、TEM-Status **96.67–100%**。证据均长 94–118 token，较 session-aware RAG 少 **48.75–56.73%**。LoCoMo 1540 题、1024-token 预算：相对 session-aware RAG 保守下界差 **7.92 / 10.58** pp（Llama / Qwen）；此设定下标签与 Unmarked hybrid 接近，增益主要来自证据组织。
   - 局限：Discussion——假定显式单值更新与源序即时间序；迟报、同会话冲突、可并存偏好需有效时间或冲突语义；LoCoMo 上标签几乎不加分。失败条件：Overwrite 却宣称可答历史；或只源序堆事实不标 historical；或把 LoCoMo 增益全归功于标签而非 hybrid 组织。
   - 对办公 Agent 或 Agent 基础设施的意义：CRM/人事档案类「当前值 vs 历史值」可验收为 **版本组保留 + 检索不删旧 + 证据显式标历史**。生产可对标：历史问 hit 与证据 token；同内容有无标签的对照；禁止「只留最新事实」冒充长期记忆。
