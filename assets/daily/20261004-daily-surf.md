1. **[Mem++: Non-Destructive Memory for Long-Term Organizational LLM Agents](https://arxiv.org/abs/2610.02002)**
   - 元信息：2026-10-02（arxiv pastweek Fri listing；abs dateline：Submitted on 1 Oct 2026；cs.CL；代码 AIDAChip-Inc/mem-plus-plus）；预印本；主题标签：Agent Memory / 组织记忆 / 非破坏整文档存储 / as-of 时序检索 / OrgMemBench·LoCoMo·LongMemEval-S；分级：S
   - 核心问题：企业知识工作的记忆不是单叙述者对话——邮件/工单/纪要/政策由多人独立写入，修订常以「新文档」出现而非原地改旧文；写时蒸馏（事实抽取/图边/覆盖）会在提问前固定可答范围，并抹掉理由、条件与审批痕迹。能否把版本抉择推迟到读时，同时仍答「现在成立什么 / 某日成立什么 / 谁改过」？
   - 机制/设计：Mem++=\(\langle\mathcal{R},\mathcal{C},\Phi\rangle\)。写路径：每文档整存 \(r=\langle x,a,t,\mathbf{e},\sigma\rangle\)（全文/作者/事件日/句向量/状态），只调冻结编码器，无生成模型；append-only，空文或同作者域精确重复跳过。可选 consolidation \(\mathcal{C}\)（默认关）按余弦聚簇后标 conflict/restatement/distinct，冲突只改 \(\sigma\) 标 superseded、不删原文。读路径 \(\Phi\)：先按 as-of \(\theta\) 取 \(\mathcal{S}_\theta=\{r\mid\mathrm{active},t_r\leq\theta\}\)，再 lex/tag/vec 三索引加权 RRF（\(\gamma=60\)），\(k=50\) 中留 3 个最新日期位；证据按日期+作者头渲染给冻结答题模型。Memg++ 另加写时三元组图，但三元组无日期、不受 as-of 约束。
   - 证据：OrgMemBench medium（443 文物/157 线程/18 月、73 题·247 rubric 面）。gpt-4.1-mini：Mem++ Overall 57.6 vs RAG 55.0 / A-Mem 44.5 / Zep 41.0（相对最强记忆基线 +13.1）；Supersession 67.7、Audit Replay 83.0 领先。gpt-4o-mini：Mem++ 44.2 / Memg++ 44.4 vs Zep 36.2（+8.0）。LoCoMo LLM-judge：81.5 / 77.4（两骨干均最高）。LongMemEval-S：Mem++ 72.2/74.7，Memg++ 72.4/75.3。消融（claude-sonnet-4-6）：去向量腿 Org −35.7、LongMem −76.0；开 consolidation / fact index / Memg++ 不升反降约 0.9–2.6。
   - 局限：结论自承组织评测仅 OrgMemBench 一合成组织 73 题；Contradiction 上 RAG 高 27–28 点，Justification Chain 全体 <23；仅 15 道 Audit Replay 带 as-of；Org 答题上下文截前 4 万字符≈19 行，recency 位与图三元组常进不了答题窗。失败条件：写时覆盖旧决策（Mem0 式）；把无日期行丢进 as-of 查询；或依赖 Memg++ 图边却未做时序过滤。
   - 对办公 Agent 或 Agent 基础设施的意义：直接给「政策/审批/多作者文档」记忆合同——原文永存、写近零 LLM、版本抉择在读时+as-of。生产可把「摘要不得替换源文档」「supersede 只改状态」「审计回放必须可按日取证」做成记忆回归门，并单独盯矛盾对账与论证链题型。

2. **[AutoCompact: Learning When to Compact Context in Long-Horizon Coding Agents](https://arxiv.org/abs/2610.02163)**
   - 元信息：2026-10-02（arxiv pastweek Fri listing；abs：Submitted on 1 Oct 2026；cs.CL；SMU/NTU/Harvard）；预印本；主题标签：Context Engineering / 主动上下文压缩 / judge 在线纠偏·SFT→GRPO / SWE-bench·SWE-PolyBench；分级：S
   - 核心问题：长程 Agent（此处为仓库级编码）轨迹里探索假设、失败尝试与冗长工具输出会过期；仅按长度阈值压缩会卡在未完成阶段，仅学「何时调 compact」又不够——摘要可能漏工作态，压缩后动作也可能无视摘要。能否把 when / what / how-continue 一齐写进策略？
   - 机制/设计：脚手架增加可主动调用的 `compact()`：用 `# Auto Context Summary` 工作态摘要替换更早历史，保留原任务。数据：基座在 SWE-rebench 上 rollout，GPT-5.5-Codex judge 逐步审 trigger/摘要/压缩后动作，纠偏后再执行，得 1,052 条轨迹（24% trigger / 53% 工作态 / 23% 续行）做 SFT；再在 SWE-Gym 上 GRPO，仅二值测例通过奖励，轨迹按 compact 切段共享 advantage。推理无 judge。骨干 Qwen3-Coder-30B-A3B；评测 SWE-bench Verified 与 SWE-PolyBench Verified（三跑均值），并扫 $0.10–$4.00 推理预算与 256K / 16K 强制压缩 fallback。
   - 证据：SWE-bench / PolyBench pass：AutoCompact 39.6 / 24.5 vs Base 30.4 / 19.5（+9.2 / +5.0）；SFT-only 32.2 / 21.7；优于 SelfCompact、SWE-Compressor、CompactionRL。256K 下无轨迹触强制阈值，SFT 仍全面超 Base；RL 相对 SFT 再 +7.4 / +2.8，低预算增益最大。同 checkpoint「忽略 compact」：pass 下降，在 $0.10 差 19.9 点。行为：主动 compact 任务占比 Base≈0 → SFT 44.3% → RL 58.5%；关键态遗漏 3.1%→0.2%，下一动作遗漏 8.2%→2.2%。
   - 局限：Limitations——RL 训练序列 32K，短于评测 256K；仅单一 REPL 脚手架；主域为编码 Agent 非邮件/日历写闸；摘要质量部分靠关键词筛+抽检。失败条件：只 SFT 仿摘要却不保证态–动作自洽（文中 django-13809：SFT 摘要仍提「直接收工」致 SyntaxError）；或部署只开长度 fallback、关掉主动 compact。
   - 对办公 Agent 或 Agent 基础设施的意义：把 context engineering 从「外挂压缩模块」推进到「策略内何时压、留什么、怎么接着干」——办公长跑（跨附件排查、多步改表）同样适用。生产可把「阶段完成后主动压」「摘要须含当前结论+下一动作」「同权重忽略 compact 不得掉质量」做成 harness 回归，并与长度 fallback 叠加而非互斥。

3. **[Right Answers, Wrong States: Hidden Information Failures in Multi-Agent Collaboration](https://arxiv.org/abs/2610.01244)**
   - 元信息：2026-10-02（arxiv pastweek Fri listing；abs：Submitted on 1 Oct 2026；cs.CL；西交大+NUS+A*STAR；代码 whr000001/OffQuery）；预印本；主题标签：Multi-Agent / 共享状态可靠性 / off-query failure / 证据校验·状态重建 / OffQuery·ReGround；分级：S
   - 核心问题：多 Agent 常只按终答对错评价；协作却可能在「当前题答对」的同时留下被污染的共享信息态（off-query failure）——当前查询未触达的错误事实，会在后续任务/Agent 复用时爆雷。如何分开度量证据校验、状态重建与任务求解，并显式修好共享态？
   - 机制/设计：OffQuery 将实例拆为可靠全局态 \(C^\star\)、共享上下文、跨 \(n\) Agent 私有观测；主设置恰一误导源。三任务：T1 识别不可靠源；T2 原子事实级重建 \(\hat{C}\)（保真正事实、剔除注入负事实，FActScore 式）；T3 当前题准确率。域：Healthcare（MediQ→Healthcare-S/I）与 Disaster Response（CrisisFacts）。ReGround：先仅凭私有证据做冲突引导校验（迭代冲突对→候选池→对照池外证据打分），再把共享上下文拆原子事实并对照可信源修态，最后只在 \(\hat{C}\) 上答题——「先校验再共享」。
   - 证据：21 模型×设置平均：标准协作 T3 64.7% vs T1 14.3% / T2 43.1%（如 GPT-5 Healthcare-S：T3 86.2 但 T1 10.9、T2 33.2）。仅分布式可靠信息已使 T2 相对 Oracle −34%，共享污染再使其跌至约 −66%。ReGround 相对标准协作平均相对增益 T1 +309.0%、T2 +82.9%、T3 +17.6%，21/21 设置三指标全升；相对 Voting/Robin/Manager 等协议基线 T3 也全面最高。机制：正确决策解释中不可靠事实仅 13.9–19.2% 出现（错误决策 60.9–71.7%）；100 例「T3 对但态仍脏」扩成更广临床计划后 43% 与可靠态计划不一致。多误导源 / 分散误导下 ReGround 仍从 45.2→60.8、26.4→49.7。
   - 局限：Appendix A——主域仅医疗/灾害；主设置单误导源（虽有多源压力测）；片段内共享态、非跨会话持久记忆累积；构造与 T2 判分含 LLM（有三人审 κ=0.84 与跨裁判相关）。失败条件：只盯终答 Acc；或把污染共享上下文在私有证据核验前灌进讨论（Pre-discussion 在共享已污染时稳定伤分）。
   - 对办公 Agent 或 Agent 基础设施的意义：给多角色办公协同（会诊式工单、跨部门事实汇总）一条验收轴——答对当前问 ≠ 共享知识库可复用。生产应把「冲突证据先闸」「共享态原子事实核对」「后续任务复用前再验态」做成多 Agent harness 门，而不是只加更大模型或换讨论拓扑。
