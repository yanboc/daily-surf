1. **[Learning What to Remember: Long-horizon Counterfactual Memory Optimization](https://arxiv.org/abs/2609.37930)**
   - 元信息：2026-09-29（arxiv abs；v1 submitted 2026-09-29）；预印本；主题标签：Agent Memory / 记忆改写信用分配 / Memory Gain Policy Optimization（MGPO）/ 继承效用剥离 / SciREX·AIPAN 迁移；分级：S
   - 核心问题：持久文本记忆的写入是信用分配问题——改写可能很晚才有用，而观测到的下游效用常大量继承自改写前的记忆状态；只按「记忆状态好坏」优化，会把旧信息的功劳算到最新 rewrite 上，学不出「该记什么」。
   - 机制/设计：解耦可训 writer \(\pi_\theta\) 与冻结 reader \(\mathcal{E}\)。流式输入 \(c_t\) 更新有界记忆 \(m_t\sim\pi_\theta(\cdot\mid m_{t-1},c_t)\)，\(|m_t|\leq B\)。对同一目标 \(j\) 计状态效用 \(F_{t,j}\)，定义改写边际 \(\Delta_{t,j}=F_{t,j}-F_{t-1,j}\)，Memory Gain \(MG_t=\sum_{j\geq t}\Delta_{t,j}\)；回报 \(G_t=\sum_{k\geq t}MG_k\)。正文证明 \(MG_t=r_t^{\mathrm{fact}}+\Phi_{t+1}-\Phi_t\)（\(\Phi_t=\sum_{j\geq t}F_{t-1,j}\) 为继承效用），故 \(G_t=G_t^{\mathrm{fact}}-\Phi_t\)，期望策略梯度与事实目标一致，但样本级信用剥离继承。用位置 EMA 校准优势后做 PPO 式 token 裁剪目标。评测主场景为文档级 IE：SciREX（Method/Task/Material/Metric 聚类与二元关系），块长 1024、记忆帽 256；writer Qwen3-8B、reader Qwen3-14B；另无仅 SciREX 训练的 writer 零适配迁移 AIPAN-10K 隐私政策抽取，并报告跨 reader 复用与 BABILong 选测。
   - 证据：SciREX：MGPO 记忆均长 43 vs MGPO-base 202（−78.7%），实体簇 F1 51.3、关系 F1 26.5，相对 Direct Readout +30.9%/+60.6%；优于 Mem0、MemAgent、HiMPO 等同表对照。AIPAN-10K OOD：实体簇 39.2、关系 22.9，超过其他 learned memory 与次优外存。信用消融：Full（MGPO）是唯一在簇/关系上稳定优于 No Memory 的变体；相对 Factual（同目标但不减继承），跨 chunk 距离精度更高。固定未训策略下，MGPO 将跨 rollout 梯度方差降 24.9%（95% CI 6.4–42.6%）。同一 8B writer 配 6 个冻结 reader（含 Llama3.1-8B、Phi-4-14B）均相对无记忆抬升。
   - 局限：Appendix G——MGPO 只隔离相邻状态边际，不显式拆多改写高阶交互；当效用需若干互补更新才显现时，增益归到「变得可观测」的那一步，粒度受限。评测主域为结构化 IE 而非办公工具副作用；训练需上三角反事实矩阵，推理虽只走事实对角，但训练成本高于单次 rollout。失败条件：把「记忆状态 F 高」当成最新 rewrite 的功劳；或只做当前目标 myopic 边际、丢掉跨块复用信号。
   - 对办公 Agent 或 Agent 基础设施的意义：给「会话笔记/客户事实/项目状态」写闸一条可验收的信用合同——应用反事实前后记忆对照 + 长地平线复用，而不是用终答或当前检索分训写策略。生产可把「改写前后同一探针题集的边际增益」做成记忆回归门，并优先压记忆长度而非堆检索量。

2. **[FOCUS: Training-Free Decision-Preserving Context Compression for LLM Agents](https://arxiv.org/abs/2609.37590)**
   - 元信息：2026-09-29（arxiv abs；v1 submitted 2026-09-29；Microsoft M365 Research）；预印本；主题标签：Context Engineering / 决策保持压缩 / 反事实 span 效用 / OfficeBench·AppWorld / 无训练测试时；分级：S
   - 核心问题：长程 Agent 的 (reasoning, action, observation) 历史线性膨胀，推理成本二次、注意力被稀释；既有压缩多靠离线学「删什么」或 token/KV 层剪枝，既贵又难适配测试时新依赖，还可能打碎工具调用结构。真正该问的是：哪些过去 span 因果上塑造未来决策？
   - 机制/设计：FOCUS 把压缩写成决策保持的 IB 目标，并用 span 级反事实效用 \(U(s_i)=D(P(Y\mid H_t,g)\,\|\,P(Y\mid H_t^{-i},g))\) 近似。测试时：历史超预算 \(\delta_{\mathrm{mem}}\) 后，轻量 draft 模型采 \(N\) 条计划草图，每步显式引用依赖 span；引用频率 \(\hat{u}_i\) 作为未来依赖分，保留 \(\hat{u}_i\geq\tau\)；再对未引用 span 做 DefensiveVerify，救回删除会致重复错误/丢因果态者。保留 span 原文，丢弃其余。默认 \(N=3\)；AppWorld \(\delta=4096\)，OfficeBench/8-QA \(\delta=2048\)。主 Agent gpt-4.1（可换 mini），draft 可同族或 Qwen3-8B/14B、Phi-4。评测：AppWorld test_normal（168）、OfficeBench test、8-objective QA（100）、WebVoyager 文本子集、\(\tau^2\)-Bench。
   - 证据：AppWorld（gpt-4.1）：FOCUS-D Acc 64.9 vs 无压缩 56.0 / ACON UTCO 56.5；FOCUS-O Peak/Dep 相对无压缩约 −35%/−60%。OfficeBench：FOCUS-O Acc 78.90 vs 76.84，Peak/Dep −47%/−73%；并行 \(N\) 时任务延迟 36.5s vs 47.2s，总 API 成本约 −37%（draft 仅约 3%）。8-QA EM 0.386（FOCUS-O）vs 0.366。gpt-4.1-mini 自压缩：AppWorld Acc 44.0 vs 35.7。Qwen3-8B 作 draft：主 Agent Acc 65.5（无压缩 56.0）。WebVoyager Acc +4.5、Peak −27%；\(\tau^2\) retail/airline 分别约 +7.1/+2.0。\(N\) 消融：OfficeBench \(N=1\to3\) Acc 71.6→77.9，再增收益饱和。
   - 局限：正文无独立 Limitations；A.10 失败模式——集合泛化计划（「对每个联系人…」）低估逐实体枚举 span，剪掉后漏处理集合成员（如 Venmo 加好友漏 1/5）；防御验证缓解但非消除。A.11：更便宜长跑可能降低敏感域监督门槛；激进压缩或删安全相关 span。依赖 draft 引用格式与 \(\delta/\tau\) 调参；主结果在 Azure gpt-4.1 设定。失败条件：集合型多实体跨应用任务上只信乐观计划引用；或把 Peak 降幅当成功却未盯实体覆盖。
   - 对办公 Agent 或 Agent 基础设施的意义：直接落在 OfficeBench（Word/Excel/Email/Calendar）与 AppWorld 生产力 API——生产可把 compaction 从「摘要过去」改成「保留影响下一步决策的 span + 救失败/鉴权态」。门禁建议：压缩后回归集合型任务（批量收件人/多行更新）与鉴权 token 是否被防御阶段救回；draft 可用小开源模型以压成本。

3. **[LatCom: Cross-Agent Latent Compression for Efficient Multi-Agent Collaboration](https://arxiv.org/abs/2609.37017)**
   - 元信息：2026-09-29（arxiv abs；v1 submitted 2026-09-29）；预印本；主题标签：Multi-Agent / 潜空间协同 / 跨 Agent 冗余 / 固定 slot 压缩 / 接收端任务效用；分级：A
   - 核心问题：潜空间 MAS 用对齐隐状态代替自然语言通信，避免编解码损失，但直接转发全部 sender 潜轨迹会使接收端上下文随 Agent 数与推理步数膨胀；现有做法常「每 sender 独立压缩再拼接」，t-SNE/CKA 显示跨 Agent 仍大量重叠冗余。
   - 机制/设计：LatCom 将多 sender 对齐潜轨迹聚成带任务/身份/分隔符的序列 \(U\)，用 \(K\) 个可学习 slot 映射为接收端可读消息 \(M\in\mathbb{R}^{K\times d}\)，优化冻结 receiver 生成损失而非重建 sender 隐状态。两阶段训压缩器（sender/receiver 全程冻结）：(1) 单 sender 可读性——任务损失 + 接收端对比（匹配 vs 错配轨迹）+ JS/均值对齐，防学成无视 sender 的 soft prompt；(2) 多 sender 融合——2–6 个 sender，金证/非金/混合证据实例，多源对比惩罚替换金证源。主设：三角色层次（math/science/code）+ receiver；每 sender 40 潜步，压成 \(K=64\) slot。骨干 Qwen3-4B/8B；训练数据 HotpotQA/MuSiQue（过滤单模可解与压缩前不可答）；评测 GSM8K、ARC-E/C、MedQA、MBPP+、HumanEval+、GPQA-Diamond。
   - 证据：Qwen3-4B 七任务均值 Acc 76.27（LatentMAS 75.92、InterLat 74.37、TextMAS 75.64）；相对 LatentMAS 均速约 \(2.46\times\)，输出 token 约 −70.3%。相对独立压缩再拼接的 InterLat，均值 +1.9（4B）/+1.77（8B）。消融：Stage2 相对仅 Stage1 均值约 +9.0pp；GSM8K 上去掉 \(\mathcal{L}_{\mathrm{align}}/\mathcal{L}_{\mathrm{con}}/\mathcal{L}_{\mathrm{ms}}\) 分别 −11.65/−5.53/−2.37。Sender 增至 8 时 GSM8K/ARC 均值约掉 2.2pp；\(K=8\) 明显掉分，\(K=32\)–\(64\) 较稳。压缩步均约 0.116s。
   - 局限：Limitations——依赖同模型族对齐隐表示，异构架构/维数/分词器/拓扑未解；固定 slot 在部分代码任务上弱于全量潜中继，可能丢掉细粒度信息。评测为推理/代码榜而非办公工具链通信。失败条件：把「每 Agent 独立压缩再 concat」当已消跨 Agent 冗余；或在异构多模型编排上直接搬同族 LatCom。
   - 对办公 Agent 或 Agent 基础设施的意义：对「多专家潜通信/共享工作记忆」给出接收端预算闸——应按接收效用做跨源融合压缩，而不是按 sender 各自砍再拼。生产若走文本/JSON 总线，可类比：共享上下文写入前做跨角色去冗与固定槽位摘要，并回归「金证源被替换」类负例；异构模型间仍需显式对齐层，不能假设隐状态可直通。
