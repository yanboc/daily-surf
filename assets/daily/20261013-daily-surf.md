1. **[Test-Time Memory Construction](https://arxiv.org/abs/2610.13348)**
   - 元信息：2026-10-09（abs：Submitted on 9 Oct 2026；Mon 12 Oct 2026 列表公告；cs.CL；东北大学 / 清华 / 阿里；代码 github.com/OpenBMB/T2Mem）；预印本；主题标签：Agent Memory / 测试时记忆构建·情节元数据 cue / SearchMeta·ReadRaw 渐进 rollout / LoCoMo·LongMemEval；分级：S
   - 核心问题：长交互史上相关证据常跨会话散落；现有记忆系统多在**查询出现前**离线做摘要/图/分层固化，既贵又难适配具体问题。LazyMem 一类测试时构建又多依赖一次性检索候选，缺证据时难再开窗。能否把记忆当成推理过程中逐步演化的状态？
   - 机制/设计：**T²Mem**。(1) 离线仅用 \(\pi_{\mathrm{meta}}\) 抽轻量 episode 元数据 \(\mathcal{I}\)（事件/事实/实体/时序 cue），并保留 \(\mathcal{L}(i_k)=s_k\) 回链原文，不做重型持久记忆库；(2) 测试时轨迹 \(\tau=((r_t,m_t,a_t))_{t=1}^{T}\)，记忆 \(\mathcal{M}_t=\mathcal{M}_{t-1}\oplus m_t\)，终答 \(y=\mathrm{LLM}(q,\mathcal{M}_T)\)；(3) 工具 \(\mathcal{T}=\{\texttt{SearchMeta},\texttt{ReadRaw}\}\)：初观察 \(o_0=\mathrm{Top}\text{-}k(q,\mathcal{I})\)（主实验 \(k=5\)），SearchMeta 在未见元数据上再取 \(k=1\)，ReadRaw 沿源链读整段 raw session；见过集合 \(\mathcal{I}^{\mathrm{seen}}\) 防重复；(4) 信息够或达 \(T_{\max}=5\) 则 Answer。骨干 Qwen3.5-27B / Gemma4-31B-Instruct，检索 BGE-M3；裁判固定 Qwen3.5-Plus。
   - 证据：LoCoMo Avg——Qwen **71.69** / Gemma **71.30**（token \(\times10^3\)：8,765 / 7,274），超 LazyMem 69.84/70.49、LightMem 68.70/69.16、xMemory 68.12/67.14；Multi-Hop/Temporal 上相对 RAG/Search-o1 优势更明显。LongMemEval Avg——**84.80 / 85.20**（LightMem 77.40/77.60；LazyMem 72.60/76.20）；Qwen 上 Single Preference **83.33**（LightMem 76.67，但 Single-Assistant 仅 25.00）。消融（LoCoMo/Qwen）：Summary/Graph 元数据 Avg 68.64/62.92；w/o Metadata 69.74、w/o Rawdata 67.60、w/o Rollout **65.45**。图 2：五维记忆质量（时序/实体/完整/事实/细节）均最高；同量级 token 下准确率高于离线记忆系统；增大测试时预算持续抬升，Search-o1 弱、Naive RAG 反降。
   - 局限：正文无独立 Limitations；评测为对话记忆 QA（LoCoMo 排除 adversarial；LongMemEval 用 longmemeval_s_cleaned），靠 LLM judge；离线仍需元数据抽取；主实验 \(T_{\max}=5\)。失败条件：把一次性「先检索再拼记忆」当已测试时演化（LazyMem 模式）；或只用摘要/图元数据却关掉 ReadRaw；或去掉 rollout 却仍报与全量 T²Mem 同级。
   - 对办公 Agent 或 Agent 基础设施的意义：给「跨会话会议/邮件/工单 QA」一条**轻量索引 + 查询时按缺口读原文**合同，而不是先花大钱建全能记忆库。生产可对标：元数据与 raw 分表；多跳/时序题分项；总 token 与 LazyMem/LightMem 同预算对照；禁止只报 Overall 掩盖类别塌陷（如 LightMem 的 Single-Assistant）。

2. **[SEEDS: Preview-Guided Evidence Admission for Search Agents](https://arxiv.org/abs/2610.12932)**
   - 元信息：2026-10-09（abs：Submitted on 9 Oct 2026；Mon 12 Oct 2026 列表公告；cs.CL；NYU / NYU Shanghai；7 figures, 20 pages）；预印本；主题标签：Context Engineering / 证据准入·preview 闸 / 非前缀子集选择 / ReAct·Search-o1·九基准；分级：S
   - 核心问题：多轮搜索 Agent 常把「检索到」等同于「写进推理上下文」；固定 \(k\) 或 dyn-\(k\) 前缀又管不住「哪篇该进、进几篇」。低排名候选可能关键、高排名可能冗余或误导。如何在**当前推理态**下决定哪些候选被准入上下文？
   - 机制/设计：**SEEDS**（Selective Evidence Entry During Search）。每轮：检索 \(K=10\) 候选 → \(\operatorname{Preview}\)（本地：标题+查询关键词匹配窗约 60 token；网页：引擎 title/snippet）→ 准入策略 \(\mathcal{E}^{(i)}=\mathcal{A}(\mathcal{H}^{(i)},\mathcal{P}^{(i)})\) 可选任意子集（含空集）→ 仅 \(\operatorname{Expand}\) 全文进轨迹。可 prompt 直装到现有推理模型，也可 SFT+PPO 得 Seeds-R1。实例：Seeds-ReAct、Seeds-o1。主骨干 QwQ-32B；本地 2018 Wiki + E5；线上 Serper + Jina Reader。
   - 证据：六本地 QA（各约 500，Bamboogle 125）——Seeds-ReAct Avg EM **41.6**、#Doc **3.1**，相对多轮基线 +2.9～6.3 EM、全文消耗约 −60–79%；Seeds-o1 Avg EM **43.3**（Search-o1 42.5），#Doc 30.2→**12.6**（约 −58%）。线上 BrowseComp / BrowseComp-zh / HLE：Seeds-o1 Avg Acc **11.78**（Search-o1 9.28，+2.5），#Pages 27.81→**8.30**（约 −70%）。>5k 搜索轮：Seeds-ReAct/o1 分别有 **44.1% / 39.6%** 准入文档落在对应 top-\(|S|\) 前缀之外，约 80% 轮次偏离前缀；含答案证据命中相对 dyn-\(k\) +13.8% / +27.6%。扰动：注入 distractor 时 Seeds 准入率 <8%，\(\rho=0.8\) 时 EM 仍可 +1.3。DeepSeek-V4.1-Flash 上全文读取约 −52–61%（HLE 页约 −44%）；NQ 上 Seeds 相对同骨干 Search-o1 −1.4 EM。
   - 局限：正文无独立 Limitations；HLE 上 Seeds-o1 Acc 升但 F1 10.60→**6.66**；preview 形态无单一最优（附录 Table 7）；answer-bearing 用别名字符串代理；主表子集抽样。失败条件：只调前缀长度却宣称已做证据准入；或预览未进态就全文灌入；或只报 EM/Acc 掩盖全文 token/#Doc/#Pages。
   - 对办公 Agent 或 Agent 基础设施的意义：把「制度库/网页/附件检索」验收从召回榜推进到**进上下文前的准入闸**——预览、子集选择、全文消耗分表。生产可对标：邮件/知识库检索后不得默认 top-\(k\) 全文进 prompt；审计「本轮准入了哪些 id」；噪声命中下 distractor 准入率作回归项。

3. **[Humanize MLE Agents: Multi-Agent Session Alternation Beyond Single-Agent Limits](https://arxiv.org/abs/2610.13494)**
   - 元信息：2026-10-09（abs：Submitted on 9 Oct 2026；Mon 12 Oct 2026 列表公告；cs.AI；32 pages, 10 figures；Humanize 平台）；预印本；主题标签：Multi-Agent / 会话交替·上下文重置 / CR-SMDP·固定 \(k\) 实验帽 / MLE-bench·共享工作区；分级：S
   - 核心问题：长程单会话 Agent 会出现**推理强度与进展同步衰减**（long-horizon deceleration）；专用 harness 的相对收益又随基座变强而消失甚至反转（harness staleness）。能否在工作流层交替完整「模型+原生 harness」对，靠共享工件而非再堆定制上下文工程？
   - 机制/设计：**HMA**。(1) 形式化为 **CR-SMDP**：option 边界保留共享状态 \((W,E)\)、上下文重置为 \(\emptyset\)；每会话至多 \(k\) 次实验后交接（主实验 \(k=5\)）；(2) 定理给出交替超过单 Agent 参考界的充分条件与实验预算界，以及固定 \(k\) 中断何时保住优势；(3) Algorithm 1：两原生 Agent 在同一工作区交替，交接只传持久产物；末 **15 分钟**由另一方做 archive 终审（无测试集分数），失败回退最近候选；(4) 不改各 Agent 内部工具/上下文环，初始化不塞任务专用知识库。MLE-bench：1×A10、6 小时；对照含 /goal 单会话与 12–24h 发表工作流。
   - 证据：75 题 MLE-bench。Opus-first HMA（Claude Opus 5 ↔ GPT-5.6-sol）All **78.2%**（相对 constituent 均值 +8.0；最强单 Agent Opus 72.4；最强发表开源工作流 70.2 却用更长墙钟）。同对 GPT-first 仍 **73.3%** > 72.4。六配置、五异构对：相对 constituent 基线平均 +**6.4** any-medal，且每配置为正。小时 0–2→3–5：HMA 保留 **86.4%** 每响应输出 token，匹配 /goal 仅 **60.7%**。终审改选 8.9%，medal 结局 311→319（无回退损失）；有 medal 探索的 330 跑中终选保留率 96.7%（审前 94.2%）。补充 AOPT 核优化单跑 48h 达 878 cycles（作者对照社区榜约差 1.6%，非同裁判核验）。
   - 局限：结论明确——MLE-bench 之外的对比优势仍是未来工作；AOPT 为单跑探索；发表基线算力/时长与本文 6h 不完全对齐；High 复杂度子集仍难（单 Opus High 46.7）。失败条件：超长单会话不重置却加更多 skills/AGENTS.md；或交接时重置共享工作区；或去掉实验帽 \(k\) / 终审却仍宣称已破单 Agent 天花板。
   - 对办公 Agent 或 Agent 基础设施的意义：给长文档/表格/迭代优化类办公任务一条**工作流级多 Agent 合同**——共享磁盘态、会话上下文强制重置、按实验/步骤数硬帽交接、异厂商原生 harness 可插拔。生产可对标：6h（或等价步数）内 any-success vs 单 Agent；后半程响应长度不得塌到 /goal 水平；终审只改选不重跑全探索。

   - 核心问题：Slides/AI 搜图等主进程拉取若目标受模型或检索污染，传统「先解析校验、再让 OS 解析连接」存在 DNS rebinding 窗——校验见公网地址、连接时被打到 loopback/云元数据；再加攻击者控制的 `Content-Type` 可把 HTML/错误页存成假 `.jpg` 进演示文稿。

   - 证据：[README](https://github.com/genspark-ai/genoffice/blob/1ac9775c/README.md)（本地 AI Office / Agent CLI）；[`safe-remote-url.ts`](https://github.com/genspark-ai/genoffice/blob/1ac9775c/packages/electron-utils/src/safe-remote-url.ts)（文件头说明 rebinding 窗与 pin）；[`media-mime.ts`](https://github.com/genspark-ai/genoffice/blob/1ac9775c/apps/slides/src/main/media-mime.ts)（`rasterImageExt`）；[`safe-remote-url.test.ts`](https://github.com/genspark-ai/genoffice/blob/1ac9775c/packages/electron-utils/tests/safe-remote-url.test.ts)（`pinnedLookup` fail-closed、元数据 URL、67+ 测）；PR [#1960](https://github.com/genspark-ai/genoffice/pull/1960)（mutation：关掉 pinning 则 pin 测变红）。
   - 局限：闸只管经 `fetchWithSsrfGuard` 的远程拉；不替代用户对 AI 改稿的审阅；fake-ip 放行依赖「解析器不在攻击者控制下」前提。失败条件：自写 check-then-connect 且连接再用默认 DNS；或信 `Content-Type` 落盘 AI 拉图。
   - 对办公 Agent 或 Agent 基础设施的意义：给「Agent 代拉外链进 Docs/Slides」一条可抄合同——**校验地址集与连接地址集必须同一对象，媒体类型以字节为准**。生产可对标任何办公 Agent 的 URL 工具：重定向逐跳钉址；禁止把响应头当文件类型权威。

1. **[The AI Drafted a Reply. Who Authorized Sending It?](https://dev.to/alexander_iwizard/the-ai-drafted-a-reply-who-authorized-sending-it-11dn)**
   - 元信息：2026-10-12（Alex Agafonov；DEV Community，原文亦发 Medium；含可运行 Python 状态机 `advance` 与拒绝路径清单）；已发布；主题标签：办公 Agent 邮件外发 / 人机审批绑定修订 / 派发幂等·delivery_unknown / 审计引用；分级：S
   - 核心问题：客服 Agent 读工单、检索说明并起草回复后，专项人员点「批准」再外发——demo 里像一步，生产里却混在一起：模型说「完成」≠ 工单已处理；`approved: true` ≠ 人审；超时重试可能一信双发。如何把「起草 / 审批 / 派发 / 送达」拆成平台拥有的合同，而不是模型自报？
   - 机制/设计：模型只提案内容与下一步；应用决定转移是否授权与外写是否真实发生。(1) 分阶段结果：生成→不可变草稿修订；审阅→授权人对**特定修订**的决定；派发→邮件服务 operation id；送达（若通道可证）另事件；(2) 检索材料带 id/修订，不得把工单里「跳过审批」当新策略；(3) 审批对象=收件人+通道+正文+附件，改文/改收件人则旧批作废；审权限、撤销、策略版本须服务端再验；(4) 纯函数状态机：`draft_saved`→`review_required`；仅 `reviewer` 可 `human_approved`；`dispatch_started` 要求 `approved_revision==draft_revision`；超时进 `delivery_unknown`，禁止直接重派，须与提供商 reconcile；(5) 审计记 ticket/operation/修订/策略版本/状态转移与来源，默认引用不可变修订而非复制全文。
   - 证据：文内完整 `Case`/`TRANSITIONS`/`advance` 示例（stdlib dataclasses，不发信、不验用户）；明确列出须拒测的路径——草稿后直派、模型冒充 `human_approved`、批 v1 后改 v2、并发双 job、超时后盲重试、把 HTTP 接受当 `delivered`、跨组织/撤权请求。作者区分纯函数单测与存储/提供商集成测的证据边界。
   - 局限：示例刻意省略认证、撤权、过期、锁与持久化；不保证 exactly-once；无真实邮件 API。失败条件：把 UI 隐藏发送按钮当网关；或把模型 JSON 的 `success`/`approved` 当业务状态；或超时当「未发送」重试。
   - 对办公 Agent 或 Agent 基础设施的意义：给「读邮件/工单 → 起草 → 人审 → 外发」钉死 **修订绑定审批 + 派发与送达分态 + 未知结果先调和**。生产可对标：外发工具只接受授权应用命令；改稿清批准；审计能回答「哪次修订、谁批、提供商回了什么」。

2. **[Build an AI Agent, Stage 3: Define Responsibilities, Permissions and Hand-overs](https://www.shiftquality.com/post/build-an-ai-agent-stage-3-responsibilities)**
   - 元信息：2026-10-12（ShiftQuality；S. West；系列「Build an AI Agent From Scratch」Stage 3；含可运行 `blueprint_check.py` / `grounding_check.py`）；已发布；主题标签：办公/需求摄入 Agent / 权限·最小特权 / 人机审批门·交接命名责任人 / 工具网关 grounding；分级：S；重复出现，值得关注（同窗前一日日报已收）
   - 核心问题：受监管组织里「需求摄入」Agent 若只靠岗位式角色与 system prompt「不得发明需求」，影子跑会把「经纪商查看理赔状态」扩成「是否也可更新状态」——多出来的动词一旦外发就被业务当成新范围。如何把责任写成可测的动作、权限、门禁与交接？
   - 机制/设计：每条责任拆六环——责任 → 具名 action → 副作用类（read/draft/write/irreversible）→ 自主级别 → 审批门（谁批、只答一个问题）→ 失败可测测试。画布存 JSON，`blueprint_check.py` 在 CI 校验：共享服务账号、draft 挂在 write 工具、禁止项只写 prompt、交接指向「a human」、门禁无审题等一律 FAIL。生产蓝图：独立身份 `svc-req-intake-agent`、三读三草稿 scope、禁止 merge/外发/改优先级；工具网关落库前做**字面引用 grounding**；六类交接各钉命名负责人。自主天花板 L2：读 L1，提案/草稿/交接 L2，外发与接受为 L0 未授权。

   - 局限：场景为合成受监管保险 intake，数字为示意；评测阈值先于结果设定；kill switch 尚未演练；L3 动作超出本阶段。失败条件：从原型工具清单反推权限；交接写「交给人」；「永不」只写在 prompt；蓝图不随新工具/scope/模型版本同 PR 变更。
   - 对办公 Agent 或 Agent 基础设施的意义：给「读文档/需求库 → 起草澄清或纪要 → 人审再外发」一条可 CI 的**权限合同**：禁止项必须在工具/凭据层不可达，draft≠write，交接必有命名主人。生产可对标：独立 Agent 身份、scope 双向检查、落库前 verbatim grounding、诱导扩 scope 评测与分析师抽样并列。

3. **[The Prompt Is Not the Permission: Securing the Agentic SDLC](https://vinny.dev/blog/2026-10-12-the-prompt-is-not-the-permission-securing-the-agentic-sdlc/)**
   - 元信息：2026-10-12（Vinny Carpenter；一手工程长文约 2.5k 词 / 13 分钟读）；已发布；主题标签：Agent 基础设施权限 / 执行边界·平台拒绝审计 / 不可信输入与人审规格闸 / 工具可达面；分级：A
