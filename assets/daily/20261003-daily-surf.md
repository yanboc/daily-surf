1. **[MemFit: Efficient Long-Term Agentic Memory](https://arxiv.org/abs/2610.00872)**
   - 元信息：2026-10-01（arxiv abs；v1 submitted 2026-10-01 00:44:33 UTC；cs.AI；代码 mitchellpiehl/MemFit）；预印本；主题标签：Agent Memory / 追加原文存储 / 段摘要索引 / LLM-free 多路检索 / LoCoMo·MemGallery·LongMemEval-S；分级：S
   - 核心问题：多数长程记忆系统在写入时用 LLM 做 consolidate/重写，既贵又慢，且压缩会丢表面细节；纯语义检索又易把「像但不对」的记忆捞进上下文（context pollution）。能否让写路径几乎不调 LLM、读路径仍精确？
   - 机制/设计：每轮对话原样写入 append-only episode store（时间戳/说话人/序列号），只过冻结句向量编码器；BM25 + 稠密索引双通道，写入不重写已存内容。TextTiling 按嵌入切段，每段一次 LLM 写 ≤200 token 双句摘要，摘要只作索引并保留成员 episode ID，不替代原文——旧事实与更正并存，抉择推迟到查询时。检索四阶段：双索引各取 top-60 → 摘要溯源扩池 + PRF（取 top-2 的 12 个最稀有词再查）严格加法扩池 → cross-encoder 对 top-50+扩池重排，pack \(k=10\)，邻域 \(w=1\) → 按时间序+绝对日期喂 reader 一次抽取。多模态：图注拼进 episode 文本走同一检索，MLLM 读包时再带图。
   - 证据：LoCoMo（排除 adversarial）：Qwen3-8B 均 F1 44.19 vs SimpleMem 33.45；GPT-4.1-mini 50.26 vs 43.24；Gemma3-27B 45.42 vs 28.98；GPT-4o 49.33 vs 39.06。MemGallery（Qwen2.5-VL-7B）F1 67.66 vs A-MEM 62.28。LongMemEval-S（~115k token/题，GPT-4o-mini）Acc 64.60，略超 LightMem 64.29、明显高于 Full context 56.80 / Mem0 53.61。效率（LoCoMo×Gemma3-27B）：相对 LLM-写记忆系统少 81–87% LLM 调用、构建成本约 −82–88%；整库构建 946s（索引 15s）vs SimpleMem 3.7k / Mem0 49.8k s。消融：去掉邻域窗 F1 −1.86；去掉全部扩池/摘要退回 plain retrieval F1 −3.32（\(p<0.001\)）。
   - 局限：Appendix E——无写时 consolidate 时跨会话合成更依赖检索，multi-hop 上可不敌写时预连边的 SimpleMem（如 GPT-4.1-mini multi-hop 41.58 vs 43.46）；模态目前仅文本+图。Ethics：原文永存、无自动删除，部署需用户删除/保留期/访问控制；未校验写入可被记忆注入；LongMemEval-S 上仅拒答约 80% 不可答题目。失败条件：把段摘要当最终证据而不回落原文；或无删除闸却把全量 verbatim 当已合规记忆。
   - 对办公 Agent 或 Agent 基础设施的意义：给「客户偏好 / 项目往来 / 跨会话事实」一条可验收写合同——写路径近零 LLM、派生摘要必须可溯源到原回合，读默认回落原文+邻域。生产可把「摘要只索引」「旧值与更正同检」「用户删除须双索引清掉」做成记忆回归门，并单独盯 multi-hop / 跨附件合成任务。

2. **[Beyond Memory: Harnessing Long-Horizon Agents with Explicit Belief States](https://arxiv.org/abs/2610.01415)**
   - 元信息：2026-10-01（arxiv abs；v1 submitted 2026-10-01 10:21:46 UTC；cs.AI；南开+阿里+清华；代码 luoyu100/PoS）；预印本；主题标签：Context Engineering / Agent Memory / 显式信念态 / Belief Trapping 恢复 / ALFWorld·LOCA·RCA-100·ClinDiag；分级：S
   - 核心问题：长程 Agent 的轨迹与压缩记忆保留证据，却不保证对「当前世界仍成立什么、还差什么」有可修订、可检验的估计；隐式信念会卡住（Belief Trapping：循环、漂移、停滞），而多数方法只会截断或停机，不会在线恢复。
   - 机制/设计：PoS 维护任务条件信念 \(B_t=(W_t,G,\Delta_t^E,\Delta_t^A)\)——Entity–State–Relation 世界估计 + 目标 + 认知/达成缺口；每步选 active gap，动作 \(\pi(\cdot\mid B_t,\Delta_t,\mathcal{C}_t)\)。候选更新 \(\widetilde{B}\) 经 Belief Sentinel 查内部冲突与外部证据支持后再提交。健康度用缺口持续、进度停滞、信念复发三信号检 Trapping，再按动力学×缺口类型组合恢复约束 \(\mathcal{C}_t\)。评测：执行侧 ALFWorld valid_unseen（134）与 LOCA-Bench；诊断侧 RCA-100（103，joint=故障类型∧根因实体）与 ClinDiag；骨干 Qwen3.7-Plus / Kimi-K3 / GLM-5.3；对照 Raw Trajectory、ACON、PACE、HiAgent、LongHorizon-Harness。
   - 证据：四基准×三骨干均为最高。Qwen3.7-Plus：ALF 88.81 vs 最强基线 LongHorizon-Harness 72.39（相对 +22.68%）；RCA joint 38.83 vs PACE/HiAgent 28.16（+37.89%）；LOCA 56.38、Clin 45.03。去掉 Consistency Validation：ALF −14.93、LOCA −11.81；去掉 Trapping Diagnosis：RCA −4.85～−6.79、Clin −2.65～−3.97。Trap 形态：ALF 偏 cycle，LOCA/RCA 偏 drift（~56%），Clin 偏 static stagnation（~78%）；分解式恢复优于泛化「请恢复」提示。成本：RCA 上 Task Agent token −20.9%，但总 token ×5.06（Sentinel/信念维护开销）。上下文缩放：LOCA 8K→256K 时 PoS 在 96K–256K 更稳，256K 领先最强基线约 10.7–16.0 点。
   - 局限：结论承认总 token 显著更高，降开销是开放问题；无独立 Limitations 节。主域为家居执行/故障定位/临床问诊，非邮件日历写闸。失败条件：只建信念结构却关掉 Sentinel（矛盾 State 入库）；或检测到 trap 却只用通用恢复提示；或把「总 token 更低」当成功却未盯 joint/成功是否回落。
   - 对办公 Agent 或 Agent 基础设施的意义：把上下文管理从「留/压历史」推进到「可审计的当前世界态 + 未解缺口」——适合跨工具长跑（改表、查工单、根因排查）。生产可把「世界态须证据支持」「缺口无进展则换策略」做成 harness 健康探针，并接受为信念维护付推理预算，而不是只比压缩比。

3. **[Global Coherence: When Every Agent Is Right and the Team Is Still Wrong — A Local-to-Global Semantic Foundation for Multi-Agent Collaboration](https://arxiv.org/abs/2610.02036)**
   - 元信息：2026-10-01（arxiv abs；v1 submitted 2026-10-01；cs.MA/相关；Tote AI）；预印本；主题标签：Multi-Agent / Context Engineering / 全局一致性 / Observation-Aliasing / commit 闸·共享预算 / TeamBench·τ²-bench；分级：S
   - 核心问题：多 Agent 协作中每步局部都「对」，合成结果仍可错——要么上下文缺区分行动的关键事实（observation aliasing），要么局部视图两两一致却无法胶合成一个世界、或各自合法消耗却击穿团队共享约束。这是状态/ harness 问题，不是再加大模型能单独解决的。
   - 机制/设计：Observation-Aliasing 不可能定理：策略能从观测保证合法动作 ⇔ 所有与观测一致的世界共享同一可行动作集；\(k\) 个不可区分世界且合法动作互斥时，最优随机成功恰为 \(1/k\)。第二类失败：环上局部一致翻译可不闭合、共享预算无法靠各 Agent 独立检查。框架 \(\mathfrak{X}=(H,\mathcal{C},\mathcal{G},\mathcal{F};D)\)：重叠拓扑、动作范畴、编码群胚（环路须回单位）、层胶合条件、以及只保留「仍影响合法未来」的历史态 \(D\)。设计原则：模型提案，拥有状态的 harness 在 commit 决定是否放行；经理 Agent 若只见摘要仍受同一不可能界。
   - 证据：九项研究（多项预注册）。Study I：可见决定性事件时 40/40；隐藏后多推理/角色/投票臂 12–17/40，与 \(1/3\) 猜兼容；补一句缺失事实或可读该事件的工具 → 40/40。Study IV（TeamBench，共享 20 次调用）：普通队超支 5/5，展示实时计数仍 4/5，commit 强制或角色 escrow → 0/5，任务进度未明显下降。Study V（τ²-bench Telecom，222 集）：策略规则破坏上与普通策略检查打平；静默撤销已提交变更时 harness 1.00 vs 普通/调用时检查 0.07。本体对齐：45 网中 23 有 pairwise 看不见的同本体碰撞；分裂视图 Agent 9/40 复现，网络级检查全检出（send-to-all 修复 F1 0.796→0.774）。依赖引擎/耦合求解器已拥有相关态时与 harness 打平。
   - 局限：正文自承——单模型族（gpt-6-sol）、TeamBench 等小面板（如预算实验 5 seed）、部分失败为注入而非自然频率；整体设计程序尚未端到端对照实验。失败条件：以为「给每人看计数/摘要」已治理共享配额；或把经理 Agent 当全局真相所有者却不持 commit 权威与完整区分信息。
   - 对办公 Agent 或 Agent 基础设施的意义：直接钉「多角色改文档/花共享额度/跨系统对齐」的基础设施合同——关键区分必须进上下文或由 harness 拥有；共享预算/版本/身份碰撞须 commit 闸或 escrow，不能靠各 Agent 自觉。生产可把「团队工具调用帽」「静默 undo 检测」「身份环路检查」列入多 Agent 办公编排回归，先问「谁拥有该不变量」再问「要不要更大模型」。

   - 元信息：2026-10-02；已发布（作者一手工程长文；产品团队 MCP 信任边界实践笔记）；主题标签：Agent 基础设施 / MCP 工具投毒与描述漂移 / 写路径人审 / 读路径污染闸 / 参数绑定审批与审计；分级：A
