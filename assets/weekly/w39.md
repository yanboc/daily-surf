## 概述

这一周的主线是 **「记忆怎么写、上下文怎么压、副作用怎么批」三件事同时工程化**。论文侧密集出现隐私可见性记忆（AIM）、cue→原文重构（CueMem）、GUI 可回放执行记忆（EchoPath）、压缩充分性审计（Correct Now）、以及按查询分配发现/保真度的 JustMem；GitHub 周榜则一边是 ECC / context-mode / agent-skills 一类 harness 与 skill 包，一边是 OfficeCLI、knowledge-work-plugins、markitdown 把办公文档工具面推上热度；大厂博客则用 Claude Tag / One Claude / Projects、Google zero-trust Gateway 与 CC、OpenAI compaction 误对齐报告，把权限、审批与压缩控制面写进产品契约。

## 一、论文（arxiv）

1. **[AIM: A Privacy-Aware Interoperable Memory Framework for Multi-Agent Multi-User LLM Systems](https://arxiv.org/abs/2609.12320)**（预印本，约 09-14）  
   多用户多 Agent 共享记忆库，用可见性谓词拆 private/public，并统一 create/read/update/delete；自建 MUMBench。直接对应办公租户隔离与团队公告，但 public 缺事实校验与群组作用域。

2. **[CueMem: Cue-Guided Context Reconstruction for Long-Term Conversational Memory](https://arxiv.org/abs/2609.12354)**（预印本，约 09-14）  
   关系三元组作 cue，答时再映射源 turn 重构证据上下文；LoCoMo 81.10% 且相对全历史大幅省 token。范式是「记忆当线索、原文当证据」，适合邮件/会议长线程的可审计召回。

3. **[EchoPath: Execution-Level Replayable Memory for GUI Agents](https://arxiv.org/abs/2609.16635)**（预印本，09-15）  
   把已验证 GUI 轨迹固化成可门控回放的执行级记忆（IBTR 视觉重瞄准）；OSWorld 第二遍成功率约 87–93%，中位 token 相对 Synapse 量级下降。办公填表/导出可从「再规划」变成可审计过程资产。

4. **[Interactive Memory Learning for Long-Term Conversations](https://arxiv.org/abs/2609.17088)**（预印本，09-15）  
   Planner/Trigger 双 Agent + 跨会话 Truth Reward，把「存什么/何时取」做成可学策略；相对静态启发式显著提升 Mauve。生产上应用验收/人工分替换 LLM proxy。

5. **[ERPBench: A State-Grounded Evaluation Paradigm for Computer-Use Agents in Enterprise Software](https://arxiv.org/abs/2609.17885)**（预印本，09-15）  
   以 ERPNext 数据库真值评分，暴露「界面看似成功、库态错误」；开源模型常导航高、Database 正确率极低。办公验收应从点按钮改成业务态对不对。

6. **[Agora: Git as Shared Memory for Collective AutoResearch](https://arxiv.org/abs/2609.18094)**（预印本，09-16）  
   多 Agent 共享记忆落成 Git append-only DAG，信用只认他人复现；多样性 UCB 抑制 monoculture。可对照企业多助手并行改方案时的负结果可见与强制探索槽。

7. **[Correct Now, Insufficient Later: Auditing Update Sufficiency in Context Compression](https://arxiv.org/abs/2609.20045)**（预印本，09-17）  
   matched-current 历史对审计压缩态：当前答对 ≠ 撤销/过期/tombstone 后仍够用；latest-only / no-tombstone 在 reveal 上崩盘。给会话摘要与票据记忆定硬验收。

8. **[JustMem: Just-Enough Memory Access for Long-Term Conversations](https://arxiv.org/abs/2609.19877)**（预印本，09-17）  
   原子记忆卡 + provenance，按 \(d_q/f_q\) 在 LOOKUP / COMPOSE / REPLAY 间切换；LoCoMo / LongMemEval 精度与预算同时优于多项基线。会议/邮件回忆应按查询分配发现广度与原文保真。

## 个人点评

1. **记忆研究已从「怎么检索」转到「怎么治理与验收」。** AIM 的可见性、CoMem/Agora 的晋级与复现信用、Correct Now 的更新充分性、JustMem 的按查询访问策略，都在说：写入口、共享边界和压缩后是否仍可更新，比单纯刷 LoCoMo 分数更关键。

2. **办公 Agent 的工具面与评测面同时变硬。** OfficeCLI 把 OOXML 做成可回滚 runtime；ERPBench 用库态打假「点对了按钮」；EchoPath 则把复发 GUI 任务变成可调用记忆。三者合在一起才是可上线的文档/表单闭环。

3. **HITL 从产品开关下沉到协议与参数契约。** openai-agents 条件审批与校验对齐、mcp-airlock / Temporal harness 的 MCP 闸门、Claude 的写工具默认逐次批、Google 的意图策略——共同主题是：审批看到的必须是将执行的那份，且旁路（直调 MCP、缺省放行、拆单）必须可审计。

4. **压缩摘要已是攻击面与误对齐面。** OpenAI 的 compaction 欺骗报告，与 Correct Now 的「当前对、以后不够」在工程上是同一警告：凡靠摘要跨段续跑的改表/建簿任务，摘要要独立监控，tombstone/版本闭包要进压缩态。
